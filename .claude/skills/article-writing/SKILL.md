# Статьи и тексты: свод правил пользователя

Правила накоплены пользователем и обязательны. Их четыре набора, они **дополняют** друг друга:
пропустишь любой — текст вернётся на доработку.

## Порядок работы

### Шаг 0. Загрузи правила
Прочитай все три справочника ПЕРЕД написанием (не после):

- [references/coherence.md](references/coherence.md) — тезис, причинная цепь, три теста. **Главное.**
- [references/strong-text.md](references/strong-text.md) — 39 правил сильного текста (Клинчук).
- [references/anti-ai.md](references/anti-ai.md) — 12 запретов против «нейросетевости».

Для блога Trace Logos дополнительно действуют памяти `blog-writing-workflow`
(структура поста, RU+EN, даты, сборка) и `blog-brand-mentions-must-link` (ссылки на каталог).

### Шаг 1. Сформулируй тезис и озвучь его пользователю
Одно предложение: идея, вокруг которой строится текст. **Покажи её пользователю** до правки файлов
(«slug — тезис: …»). Это самый дешёвый чекпоинт: неверная сквозная линия правится одной строкой.

Заодно ответь себе (правила 1–3 из strong-text): зачем этот текст, какое одно целевое действие,
на какой ступени осведомлённости читатель.

### Шаг 2. Пиши черновик живой мыслью
Не пиши ПОД чек-лист — получится алгоритмический текст. Веди причинную линию: каждый абзац отвечает
на вопрос, поднятый предыдущим.

### Шаг 3. Три прохода вычитки — по одному на набор

**Проход А — архитектура** ([coherence.md](references/coherence.md)):
перестановка / удаление / «поэтому». Проверь связки между `##` — секция не должна стартовать вхолодную.
Финальный тест пересказа: одна фраза после прочтения.

**Проход Б — «нейросетевость»** ([anti-ai.md](references/anti-ai.md)):
первым делом вычисти **«не X, а Y»** — это главный паразит, встречается десятками.
Дальше: лимит 2 метафор, лимит 2 «X — это Y», рваные предложения в 1–2 слова, склейки
«а дальше начинается», канцеляризмы, размытые прилагательные.

**Проход В — сила формулировок** ([strong-text.md](references/strong-text.md)):
вывод раньше объяснения, оценки → факты и цифры, короткий глагол, активный залог, один термин —
одна сущность, убрать усилители, заголовки отвечают на вопрос.

### Шаг 4. Факты
**Ничего не выдумывай.** Всё проверяемое — проверь: данные о логотипах бери из
`logos/categories/*.json` и самих SVG, статистику из `logos/download-stats.json`, внешние утверждения
(даты редизайнов, названия шрифтов) — через WebSearch. Непроверяемое утверждение убирай, а не смягчай.

**Живые числа не вписывай руками.** Счётчики скачиваний в блоге меняются: виджет `logo-top`
пересчитывается каждой сборкой, а вписанное в абзац «11 скачиваний» через полгода начнёт противоречить
таблице над ним. Ставь `{{stat:cat/slug}}` — подставится на сборке из того же источника.
По той же причине избегай в прозе жёсткой привязки к позиции («восьмую строчку занимает…») и к порядку
внутри рейтинга: пиши так, чтобы фраза осталась верной при смене чисел.

### Шаг 5. Сборка и проверка (для блога)
```bash
npm run build
```
В выводе `битых целей: 0`. Затем убедись, что у поста есть `blog/<slug>/index.html`,
`en/blog/<slug>/index.html` и `assets/og/blog-<slug>.png`.

## Чек-лист перед сдачей

- [ ] Тезис озвучен пользователю, каждый фрагмент на него работает
- [ ] Проходят три теста: перестановка, удаление, «поэтому»
- [ ] Ноль конструкций «не X, а Y» (и «not X but Y» в EN)
- [ ] Не больше 2 метафор и 2 «X — это Y»
- [ ] Нет рваных предложений в 1–2 слова, склеек, канцеляризмов
- [ ] Оценки заменены фактами и цифрами; у каждого заявления есть доказательство
- [ ] Один термин — одна сущность по всему тексту
- [ ] Заголовки отвечают на вопрос, а не называют тему
- [ ] Каждое упоминание бренда — ссылка на каталог (каждое вхождение)
- [ ] Факты проверены по файлам/поиску, выдуманного нет
- [ ] RU и EN синхронны; кавычки: «ёлочки» в RU, прямые в EN
- [ ] `npm run build` → `битых целей: 0`

## Чего не делать

- Не проверяй правила только скриптом: регулярки не знают кириллицу (`\b` в JS) и не видят метафор,
  размытых прилагательных, оборванных связок. **Перечитывай глазами.**
- Не применяй скилл `blog-writer` из плагина — он описывает другого автора (Telegram-канал лэндолога,
  CTA на консультацию, разговорные вставки) и к справочным статьям Trace Logos не подходит.
- Не редактируй сгенерированные `blog/<slug>/index.html` — источник только `blog/posts/*.md`.
