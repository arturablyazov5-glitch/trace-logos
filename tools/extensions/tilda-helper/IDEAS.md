# Идеи фич — в очереди на реализацию

## Live CSS Preview (принято, следующее в очереди)

Сейчас: z-index — единственное свойство, которое симулируется вручную через
`el.style.zIndex` в `tick()` (см. content.js:214). Причина хака — T123 «HTML-код»
не выполняется в редакторе, эффект виден только после публикации.

Идея: обобщить механизм. Вместо симуляции одного свойства через JS —
брать весь текст стилей из carrier-блока (или всех T123-блоков с CSS на
странице) и вживую зеркалить его как `<style>` в DOM редактора на каждый tick.
Тогда ЛЮБОЙ написанный CSS (не только z-index) виден в редакторе сразу,
без публикации.

Технически проще текущего z-index-хака: не нужно симулировать по свойству,
достаточно инжектить сырой CSS-текст в `<style>` тег.

Критерий, почему это сильная фича (не как border-radius-на-блок):
физически невозможно увидеть кастомный CSS без публикации иначе,
и убирает цикл «написал код → сохранил → опубликовал → проверил → не то →
переделал» для всех будущих задач, а не для одной.

## Отклонено

- Страховка от breakpoint-бага (предупреждение о нарушении порядка настройки
  адаптива в Zero Block) — слабая идея, не в приоритете.
- Виртуальные CSS-поля по одному свойству за раз (border-radius, sticky,
  ::selection и т.п., по аналогии с z-index) — слишком узкоспециализированные,
  не решают ничего сверх того, что тривиально сделать одной ручной правкой.
