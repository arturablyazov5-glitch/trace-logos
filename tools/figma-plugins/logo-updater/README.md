# Trace Logo’s — Обновление логотипов

Локальный Figma Design плагин для десяти английских и русских библиотек Trace Logo’s.

## Запуск

Figma Desktop → Plugins → Development → Import plugin from manifest… → выбрать `manifest.json` в этом каталоге. Затем в нужном файле: Plugins → Development → Trace Logo’s — Обновление логотипов.

1. При открытии проверка запускается автоматически. **Проверить актуальность** повторяет проверку — загрузить `https://trace-logos.ru/logos.json` и оригиналы брендов, уже находящихся в файле.
2. Посмотреть список изменений и снять отметки с ненужных обновлений.
3. **Обновить выбранные** — заменить только выбранные бренды во всех найденных копиях на двух страницах.
4. Повторная проверка не предлагает уже установленные обновления. Отмена: Cmd+Z / Ctrl+Z.

Открытый файл обрабатывается целиком, выделение не нужно. Каждый из десяти файлов запускается отдельно: Plugin API не редактирует другие закрытые файлы. Плагин работает и в дубликатах с той же структурой.

## Что сохраняется

- Объекты COMPONENT и их ID, key, названия `trace-logos/<category>/<brand>`, свойства и принадлежность к вариантам.
- Существующие INSTANCE: плагин не вызывает detach/swap и не создаёт общие библиотеки или Slots.
- Внешние фреймы логотипов на Cover, их ID, расположение, поворот, размеры и оформление.
- Карточки, шапка, подписи брендов, Auto Layout, сетка, обложка.
- Все логотипы, для которых не выбрано обновление.

Меняется только внутренний узел исходной иллюстрации. Он вписывается пропорционально в существующий контейнер. SVG импортируется через `createNodeFromSvg`; PNG остаётся растром. Внутренние VECTOR/FRAME/RECTANGLE ID меняются, поэтому ручные overrides внутренних слоёв найденных локальных экземпляров блокируют обновление бренда. Внешние экземпляры в других файлах недоступны для проверки: не применять обновление при известных overrides внутренних векторов в таких файлах.

## Как определяется изменение

Содержимое оригинального файла сравнивается по SHA-256, а не по дате или имени. Кэш обходится уникальным query и `cache: no-store`. URL страницы каталога сохраняется как идентификатор бренда: последующее переименование бренда на сайте не ломает соответствие. Имена компонентов плагин не переименовывает.

Для известных исходников этих десяти файлов включён небольшой исторический индекс SHA-256. При отсутствии истории первичная сверка использует импорт оригинала и, при различии структуры, PNG-рендер двух иллюстраций шириной 512px и их RGBA-пиксели (допуск 0,1/255 на канал для округления старого импорта). Временный импорт удаляется, исходный компонент не меняется. После сверки записывается только невидимая метаинформация на внешнем компоненте/фрейме (`setSharedPluginData`, namespace `trace_logos_updater`). Снимок содержимого обнаруживает последующие ручные правки. Ручные правки, сделанные до первой фиксации известного исторического исходника, следует проверить в первоначальном списке изменений: до сохранения baseline плагин не знает историю редактирования файла.

Сначала готовятся новые иллюстрации всех копий одного бренда, затем выполняется замена. Ошибка при подготовке/вставке откатывает бренд; другие выбранные бренды могут завершиться независимо. При конкурентной правке после проверки бренд пропускается.

Нет автоматического добавления новых брендов, удаления исчезнувших логотипов, выбора Full, old/seasonal вариантов, изменения числа карточек или публикации в Community. Недоступный файл, неоднозначное имя, comingSoon, ручные правки, вложенные компоненты и локальные overrides показываются как пропуски. При смене формата стандартная подпись SVG/PNG обновляется на языке файла; название бренда сохраняется.

## Исходники и проверки

`code.js` — Figma-часть; `ui.html` — интерфейс, сеть, SHA-256; `legacy-sources.json` — читаемый исторический индекс, уже включённый в `code.js`. Сборка плагину не нужна, npm-зависимостей нет. Не редактировать исторические хеши после изменения логотипа на сайте.

Проверки: `node --test tools/figma-plugins/logo-updater/tests/*.test.js`.

Плагин локальный, не опубликован в Community. Сайт и файлы Community сам не публикует.
