# Плашки в компонент

Локальный Figma Design плагин набора Trace Logo’s. Собирает выбранные похожие плашки в один главный Component и его Instances. Дополнительные слои включаются в общую структуру; в плашках, где их не было, они скрыты. Новые Component Properties и Slots для объединения не создаются; существующие свойства общего исходного компонента сохраняются.

## Запуск в Figma

1. Из корня `trace-logos` выполнить `npm run build`.
2. В Figma Desktop: **Plugins → Development → Import plugin from manifest…**.
3. Выбрать `tools/figma-plugins/plates-to-component/manifest.json`.
4. Выделить минимум две плашки FRAME, COMPONENT или INSTANCE. Запустить **Плашки в компонент | Trace Logo's**.
5. Нажать **Собрать компонент**. Основой всегда становится первая плашка в текущем выделении.
6. Плагин сам проверит плашки и создаст компонент, затем остальные плашки по одной. На холсте будет видно перенос текста и оформления. При блокирующей ошибке покажет её; дополнительного подтверждения нет.

Сначала использовать копию рабочего Figma-файла: автоматические проверки выполнены на модели API; работа в живом редакторе ещё не подтверждена.

Стек существующих плагинов: обычный JavaScript, отдельные main/UI, `pluginMessage`, без TypeScript и UI-фреймворка. Для модулей использован уже установленный в проекте esbuild; новых зависимостей нет. `scripts/build-plates-to-component.js` включён в общую сборку `scripts/build-all.js`. Сборка запускается **только `npm run build`**, отдельный builder вручную не запускать.

## Визуальные референсы

`../clean-layers/ui.html` и `../style-scanner/ui.html`: окно 360 px, фон `#111`, карточки `#161616`, акцент `#8a6bff`, системный шрифт 12 px, отступы 16 px, карточки со скруглением 14 px, кнопки tool-row, spinner и banners. Высота обновляется через ResizeObserver и сообщение resize, максимум 850 px. UI использует CSS и tool-row разметку Clean Layers: нейтральная кнопка, 16 px иконки со stroke 2, spinner внутри кнопки, те же отступы и banners. Сверху — шапка с иконкой и названием инструмента, снизу — общий промо-баннер Trace Logo’s с логотипами и кнопкой поддержки автора. Баннер берётся из `_shared/promo-banner.html` через `scripts/build-figma-promo.js`; ссылки открываются через `figma.openExternal`. Выбора основы, счётчиков выбранных слоёв, технических стадий и отчёта о слоях в интерфейсе нет. Сообщения выводятся через textContent; полная диагностика ошибок остаётся в консоли.

## Один клик: Analyze → Plan → Commit внутри операции

**Инстансы одного локального компонента.** Перед detach проверяется `getMainComponentAsync()`. При одном source main анализируются исходные инстансы со всеми скрытыми потомками (`skipInvisibleInstanceChildren=false`). Component-relative пути извлекаются из inherited ID до каких-либо преобразований. Исходный Component клонируется целиком, сохраняя скрытые слоты, nested Instances и Component Property Definitions. Для такого набора weighted/fuzzy matching не используется: только одинаковые исходные пути. Имена, текст, высота и значения Divider не определяют идентичность. Канонический порядок задаёт исходный Component. Неизвестный формат inherited ID блокируется с конкретной ошибкой, без угадывания.

При переносе первой карточки в клон Component её корневые TEXT/BOOLEAN/INSTANCE_SWAP значения становятся defaults существующих свойств; остальные инстансы получают свои значения через setProperties. Вложенные Divider/visibility/text свойства также сохраняются. При изменении source main во время операции операция останавливается. Исходный main не меняется и не удаляется. Для разных исходных компонентов, FRAME/COMPONENT корней и remote main используется общий режим ниже.

**Analyze общего режима.** Исходники остаются живыми. FRAME клонируется; COMPONENT становится временным Instance и отделяется; INSTANCE клонируется и отделяется. Временные деревья скрыты вне рабочей области и удаляются при завершении или ошибке. Сохраняются геометрия, layout, визуальные свойства, смешанные шрифты и диапазоны текста, вложенные связи. Проверяются внешние Instances выбранных компонентов.

**Plan.** Для каждой пары деревьев строится взаимно однозначное сопоставление. Приоритет: устойчивый `pluginData['plate-role-id']`, затем тип, нормализованное имя и токены, размеры, пропорции, состав детей, Auto Layout, геометрия, порядок и исходный вложенный компонент. Используется максимальное назначение (Hungarian algorithm) с возможностью оставить узел несопоставленным. Близкие конкурирующие оценки блокируют применение. Одно имя не считается достаточной гарантией.

Дерево основы дополняется ролями из всех остальных плашек. Повторяющиеся дополнительные элементы сопоставляются уже добавленным ролям. Их порядок определяется соседними совпавшими слоями; противоречивый порядок существующих ролей — конфликт. Роль хранит источник для каждой плашки и набор свойств для overrides. План используется внутри операции. Блокирующие конфликты показываются как ошибки; успешный план сразу передаётся в Commit.

Проверка обрабатывает по одному временному инстансу и удаляет его перед следующим; все проверочные инстансы одновременно не хранятся. Между порциями работы плагин отдаёт управление редактору.

Перед Commit кандидат реально создаётся **на временных копиях**, применяются overrides и сравниваются сохранённые свойства/диапазоны. Внешние Instances пробно переключаются на кандидат; проверяется сохранение существующего содержимого и скрытость новых элементов. Непереносимые отличия блокируют Commit.

**Commit.** Плашки заменяются последовательно: новый инстанс появляется на месте исходника, затем в него переносятся текст и оформление. Между плашками и текстовыми слоями есть короткие паузы для обновления холста. Следующий инстанс создаётся только после завершения предыдущего. Первой основой остаётся первая плашка выделения. Резервные копии и снимки всех исходников нужны до завершения; расход памяти всё ещё растёт с размером выделения.

Повторно проверяются снимки и внешние связи. Создаётся кандидат, резервируются исходники, переключаются внешние Instances. Исходники перемещаются во временный контейнер; новые узлы получают исходных родителей, индексы, размеры, outer layout, grid anchors/spans/alignment и положение. Только после проверок исходники удаляются. Результат выделяется и показывается во viewport.

**Rollback.** До окончательного удаления восстанавливаются исходные узлы с теми же ID. При частичном удалении используются резервные копии; прежний ID удалённого узла восстановить нельзя. Перед восстановлением исходников новые outputs выводятся из родительских контейнеров, освобождая занятые Grid-ячейки. Внешние и выбранные связи возвращаются на старые/восстановленные компоненты вместе с overrides. Временные узлы удаляются. Если Figma отказывает в восстановлении, сообщение перечисляет ошибки отката; абсолютная гарантия при отказе API невозможна.

## Root и вложенные Instances

Все смеси FRAME/COMPONENT/INSTANCE поддерживаются на корневом уровне. Первый выбранный элемент становится новым главным Component даже если это был INSTANCE или COMPONENT. Остальные — его Instances. Старые Components удаляются только после безопасного переноса внешних связей.

Обычные вложенные Instances сохраняют связь с local/remote компонентами; при другом источнике используется swapComponent с проверкой overrides. Если внутри вложенного Instance нужна новая структура, его временная копия отделяется, строится **локальный вспомогательный Component** с объединённым деревом. Исходная библиотека не меняется. Вспомогательные компоненты размещаются рядом с основным; в интерфейсе их количество не выводится.

Grid anchors (`gridRowAnchorIndex`, `gridColumnAnchorIndex`) только читаются. В MANUAL Grid позиция задаётся `setGridChildPosition`; в ROW_AUTO_FLOW сохраняется sibling order. Записываются только изменившиеся writable значения; ошибки содержат имя, ID, тип слоя и свойство/метод. Положение в Grid дополнительно проверяется перед удалением исходников.

## Явные ограничения

- Выделение предка вместе с потомком, корни внутри Component/Instance, remote COMPONENT как корень и неподдерживаемые root-типы блокируются.
- Неоднозначное сопоставление требует изменения структуры/имён в макете; автоматического произвольного выбора нет.
- Различающиеся vectorPaths/vectorNetwork, boolean operation, mask topology, параметры сложной геометрии блокируются. Совпадающие masks/boolean/векторы сохраняются клонированием.
- Read-only OpenType сохраняется при совпадающих значениях; различия без доступного setter блокируются ([TextNode API](https://developers.figma.com/docs/plugins/api/TextNode/)).
- Недоступные шрифты и не поддерживаемые Figma overrides блокируются до применения. Шрифты загружаются до записи текста; текстовые стили применяются перед отдельными диапазонами.
- Стили и переменные копируются, когда API допускает это. Непереносимые или несбрасываемые bindings обнаруживаются сравнением и блокируют операцию.
- Противоречия порядка слоёв и изменения Auto Layout, которые не удаётся сохранить, блокируются. Живой layout движок не воспроизводится полностью в автоматической модели.
- Перенос внешних Instances зависит от поведения Figma swapComponent и проверяется на копиях. Непереносимые overrides не игнорируются.
- Свойства вне списка снимка (`src/snapshot.js`) не входят в доказательство эквивалентности. Интерактивные реакции копируются, но их исполнение и ссылки на удалённые исходные node ID не проверяются.

## Проверки

```sh
node tools/figma-plugins/plates-to-component/tests/engine.test.js
node tools/figma-plugins/plates-to-component/tests/ui.test.mjs
npm run build
```

36 сценариев: базовый текст; Badge во второй/только первой/нескольких карточках; шесть смесей root-типов; внешние Instances; nested local и remote; дополнительные дети вложенного Instance; mixed fonts; неоднозначные FRAME/TEXT/VECTOR; masks; boolean-конфликт; absolute positioning; Auto Layout и sibling order; ошибка до Commit; ошибка при размещении; повторный запуск с role IDs; устаревший Preview; rollback внешнего swap; rollback частичного удаления и выбранной связи; неизменные и различающиеся read-only OpenType; смена основы; общий speaker-card из семи инстансов со скрытой шестой строкой, Divider, текстами, фотографиями/crop; переименование при сохранённом исходном ID; откат общего режима; изменение main после Preview; другая основа, readonly grid anchors, ручной и автоматический Grid и откат после размещения.

Это проверки на модели API, которая запрещает изменение структуры внутри Instance и возвращает новые узлы при detachInstance. Они подтверждают логику, но не являются проверкой в живом Figma. Полная сборка проекта также не подтверждает живой визуальный результат Figma.

UI отдельно проверен в Chrome при ширине 360 px: selection, одна кнопка сборки, выполнение, успех и ошибка. Ошибок JavaScript и горизонтального переполнения нет; входящие сообщения имитируются. При другом расположении Chrome задать `PLATES_CHROME_PATH`.
