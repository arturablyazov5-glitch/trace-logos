# Photo Editor — Figma-плагин Trace Logo's

**Тёмная тема** — по токенам сайта (`css/tokens.css`: `--bg`/`--bg-card`/
`--accent`/`--text-N`), не светлая дефолтная Figma-панель. Была светлой,
переключена на тёмную по прямой просьбе пользователя (2026-08-16, «в стиле
сайта»), тем же заходом, что и [Clean Layers](../clean-layers) — см. его
README, там подробный разбор, что именно поменялось и почему (контраст
page-bg/card-bg на тёмном фоне держится бордером, не одной заливкой, и т.д.).

Четыре функции для работы с `IMAGE`-заливками прямо в Figma, без
превью/кроп-рамки из веб-версии [tools/edit-image](../../edit-image/index.html):

- **Обрезать по содержимому** — фигма-версия кнопки «По содержимому» /
  `autoCropBtn` веб-инструмента. Убирает прозрачные поля вокруг картинки.
- **Восстановить размер** — если узел с фото был сжат/растянут (например
  фото 1000×1000 сжали в рамку 400×200), возвращает узлу оригинальный
  размер и пропорции исходного изображения, ставит заливке `scaleMode:
  FILL`, сбрасывает наклон узла (`rotation`), если он был, и скругление
  углов (`cornerRadius`, в т.ч. `figma.mixed` по отдельным углам) в 0.
- **Отразить (горизонтально / вертикально)** — **полноценный mirror**,
  не имитация через `rotation: 180°`. Пиксели исходника реально
  перерисовываются зеркально на canvas и перекодируются в новый PNG-файл;
  узел получает новый `imageHash`. Размер/позиция/поворот узла не
  меняются.
- **Экспорт в WebP** — сохраняет исходные пиксели image-заливки как
  `.webp`-файл на диск. Тот же алгоритм, что в веб-инструменте
  [tools/compress-webp](../../compress-webp/index.html)
  (`createOutputForFile`): картинка рисуется на canvas, дальше
  `canvas.toBlob('image/webp', quality)`. В отличие от веб-версии здесь нет
  своей ручки качества/авто-подбора/ZIP-пакета для нескольких файлов —
  фиксированное качество 0.8 (тот же дефолт, что у слайдера на странице
  сжатия), один клик — один результат, как у остальных кнопок плагина.
  **Read-only**: узел не мутируется (никаких изменений `fills`/размера/
  позиции), поэтому в собственную историю плагина (Отменить/Повторить) эта
  операция не попадает — отменять нечего.

  **Одно фото — обычный `.webp`; несколько — один `.zip`**
  (`finalizeExport()` в `ui.html`). Имя файла берётся из имени слоя,
  запрещённые символы → `_`, совпадающие имена внутри архива получают
  суффикс ` (2)`.

  **Почему архив, а не N файлов в выбранную папку (как в родном экспорте
  Figma).** Прямая запись на диск плагину недоступна: UI плагина живёт в
  песочном iframe, где File System Access API (`showDirectoryPicker`)
  заблокирован, и единственный путь наружу — браузерное «скачивание».
  Проверено на практике 2026-08-20: попытка `showDirectoryPicker` молча
  проваливалась в скачивание по файлу, Figma Desktop показывала
  Save-диалог для первого файла и отбрасывала остальные 11, пока диалог
  был открыт — 12 звуков загрузки, 1 файл на диске. **Не переписывать это
  обратно на `showDirectoryPicker`** — путь уже проверен и не работает.

  Скачивать N файлов подряд через `<a download>` тоже нельзя:
  1. Electron роняет часть параллельных загрузок — вместо `.webp` на диске
     остаются его временные файлы `.com.figma.Desktop.XXXXXX`, причём
     **молча**: клик по `<a download>` не даёт JS никакого сигнала об
     успехе записи, поэтому плагин рапортовал «экспортировано 12» при 5
     реально сохранённых.
  2. N файлов = N системных диалогов сохранения (на 1000 фото — 1000
     подтверждений вручную).

  Один архив снимает обе проблемы: одно скачивание, один диалог, один
  сигнал успеха/провала, никаких гонок. Так же устроены все плагины
  массового экспорта в Figma — ровно из-за этого ограничения платформы.
  Движок — **инлайн-копия `js/vendor/jszip.min.js`** прямо в `ui.html`
  (тот же JSZip, которым сайт делает «Скачать ZIP»): `networkAccess:
  "none"` + единственный документ `ui.html` означают, что внешний
  `<script src>` не подтянется ни из сети, ни с диска. Обновлять — только
  копированием из `js/vendor/jszip.min.js`, руками не править.

Выделяешь на холсте одну или несколько картинок → жмёшь нужную кнопку.

**Своя история (Отменить / Повторить).** Не полагается на нативный
Cmd+Z — тот отменяет всю историю документа, а не только действия
плагина. Снимок узла (заливки, размер, позиция, поворот) до/после каждой
операции хранится отдельным стеком (до 50 шагов, дальше вытесняются самые
старые). Панель истории показывается только когда есть что отменить/
повторить и сбрасывается при переключении на другой узел — старая история
чужого фото не должна быть доступна для отмены.

## Как это работает

- **`code.js`** (main thread) — находит `IMAGE`-заливки среди выделенных
  узлов (`collectEligibleImageNodes`, общая для всех трёх функций).
  - *Обрезка* и *отражение:* отправляют байты в UI, получают обратно
    обработанные байты (обрезанные / зеркально отражённые) и применяют их
    к узлу через `figma.createImage` + новый `fills`. Обрезка дополнительно
    подгоняет размер/позицию узла под новые пропорции; отражение —
    оставляет размер/позицию как есть (меняется только контент картинки).
  - *Восстановление размера:* без UI — `image.getSizeAsync()` даёт
    натуральные пиксели исходника, узел ресайзится под них
    (`node.resize`), заливке выставляется `scaleMode: FILL`,
    `node.rotation` сбрасывается в `0`, `node.cornerRadius` — в `0`
    (присвоение числа снимает и `figma.mixed`-состояние по отдельным
    углам, отдельно обнулять их не нужно).
- **`ui.html`** (iframe) — здесь есть полноценный браузерный `canvas`,
  которого нет в main thread; используется для обрезки и отражения.
  - *Обрезка:* декодирует картинку, ищет bounding box непрозрачных
    пикселей (`alpha > 8`, тот же порог, что в веб-версии), обрезает и
    кодирует обратно в PNG.
  - *Отражение:* `ctx.translate` + `ctx.scale(-1,1)` (горизонталь) или
    `ctx.scale(1,-1)` (вертикаль), затем `drawImage` и кодирование в PNG —
    зеркалит реальные пиксели, а не полагается на фигмовский трюк с
    поворотом/масштабом узла.
- Непрозрачные насквозь изображения (например JPEG без альфа-канала)
  корректно пропускаются при обрезке — обрезать нечего, как и в
  веб-инструменте.
- **Карточка выделения обновляется только по смене выделения**
  (`figma.on('selectionchange', ...)`). Переименование/ресайз слоя прямо в
  панели Figma (не в плагине) карточку не обновляют — нужно переоткрыть
  плагин или перевыделить фото. Пробовали чинить через
  `figma.on('documentchange', ...)`: падает в рантайме без
  `figma.loadAllPagesAsync()` в текущем режиме `documentAccess`, а грузить
  все страницы файла ради обновления одной карточки того не стоит —
  отклонено, оставлено как есть.

## Без сборки

**`code.js` — не build-артефакт, а рабочий файл**, единственный источник
логики main thread. Раньше рядом жил `code.ts` — typed-дубликат для
чтения, который приходилось синхронизировать руками при каждой правке;
удалён (2026-08) как источник риска разъехаться с реальным поведением без
какой-либо защиты — TS-тулчейна в проекте никогда не было настроено
(`tsc` ни разу не запускался), так что типы ничего не проверяли на
практике, только создавали иллюзию защиты. Меняешь логику — правь
`code.js` напрямую, Figma подхватывает его как есть (`manifest.json`'s
`"main"`).

## Установка в Figma

1. Figma desktop → меню **Plugins → Development → Import plugin from
   manifest…**
2. Указать `tools/figma-plugins/photo-editor/manifest.json`.
3. Выделить на холсте одно или несколько изображений → запустить плагин →
   «Обрезать».

## Несколько слоёв заливки на одном узле

- **Фото + цвет/градиент** — цвет/градиент считается мусором поверх/под
  фото, удаляется всегда (независимо от видимости), обрезается фото.
- **Несколько фото-слоёв, из них ровно один видимый** — скрытые слои
  (другие фото, цвета) удаляются, обрезается видимый.
- **Несколько ВИДИМЫХ фото-слоёв одновременно** — неоднозначно, какой из
  них обрезать; узел пропускается целиком, ничего не трогаем.
- Узлы со смешанными (`fills === figma.mixed`) заливками пропускаются.

## Ограничения

- Если у заливки уже был кастомный `imageTransform` (частичный кроп через
  режим `CROP`), пересчёт размера/позиции узла его не учитывает — после
  обрезки или восстановления заливка ставится в режим `FILL` на весь узел.
  **Отражение** заливку в `FILL` не переводит и `imageTransform` не трогает
  — если у заливки уже был кроп-прямоугольник (режим `CROP`), после
  зеркалирования всего изображения он продолжит указывать на старые
  координаты, которые теперь показывают другой (зеркальный) участок.
- **Обрезка** повёрнутых узлов: пересчёт позиции (`node.x/y`) не учитывает
  `rotation` — для наклонённых фреймов позиция может съехать.
  **Восстановление размера** это ограничение не наследует — оно явно
  сбрасывает `rotation` в `0` перед ресайзом.
