# Тесты диффа

Голый Node, без зависимостей. Запускать из этой папки:

```bash
node fuzz.js && node fuzz-cap.js && node integration.js && node metric.js && node bench.js
```

Все скрипты берут `diffHunks` из боевого `../code.js` (`live-diff.js` вырезает
блок между `const MYERS_MAX_D` и `async function applyTypography`), поэтому
проверяется ровно тот код, который уезжает в плагин, а не его копия.

| файл | что проверяет |
|---|---|
| `fuzz.js` | 22 000 случайных пар строк: хунки применяются в ожидаемый текст, не пересекаются, не дороже эталона |
| `fuzz-cap.js` | предохранитель `MYERS_MAX_D` с искусственно заниженным лимитом — рекурсивное разбиение обязано сходиться, а не зациклиться |
| `integration.js` | весь конвейер плагина на поддельной ноде Figma со стилем на каждый символ: текст совпадает с эталоном, переписанных символов не больше |
| `metric.js` | на 400 сгенерированных текстах — сколько исходных символов теряет оформление против эталона |
| `bench.js` | скорость и память против эталона на длинах 200…5000 |

`dp-reference.txt` — прежний дифф Вагнера—Фишера. Он больше не используется в
плагине и лежит здесь только как эталон: любое расхождение с ним в тексте
результата — регрессия.

Что ловили эти тесты по-настоящему: бесконечную рекурсию в предохранителе на
куске длиной в один символ (`fuzz-cap.js`) и трассу на 288 МБ в худшем случае
(`bench.js`/`fuzz-cap.js`). Обе — прямой путь к зависанию плагина насмерть.
